Frequently Asked Questions

Clear Answers About VORTEX AI

Everything you need to know about our institutional monitoring architecture, MetaTrader 5 bridge, telemetry freshness rules, and safety controls.

1. What is VORTEX AI?

VORTEX AI is a read-only monitoring and operations console built for multi-account algorithmic trading fleets on MetaTrader 5. It aggregates verified broker metrics—including account equity, margin, active positions, and trade history—into an intuitive, secure web dashboard.

2. How does it work?

A background Python daemon on your dedicated Windows trading machine reads data directly from local MetaTrader 5 terminals via the official MT5 Python API. It creates a cryptographic snapshot, signs it using HMAC-SHA256, and securely transmits it to our edge serverless gateway, which stores it in an isolated Supabase database for the web dashboard to display.

3. Which MT5 brokers are supported?

Any broker offering MetaTrader 5 with standard hedging account mode is technically supported. In our staging testbed, Vantage Markets (server VantageMarkets-Demo) has been independently verified compatible. IC Markets and Pepperstone are currently in testing. We list only brokers with empirical verification.

4. Is a demo account supported?

Yes, demo accounts are not only supported but strongly encouraged. Our active pilot runs on Vantage demo account #26179878. The dashboard explicitly marks demo accounts with a blue DEMO badge so there is never any confusion with real capital.

5. What does "STALE" feed mean?

A feed is classified as ⚠ STALE if the serverless gateway has not received a verified broker snapshot within the last 30 seconds (or if the dashboard is reading a static preflight cache). Unlike traditional platforms that mask disconnections, VORTEX AI immediately alerts operators when telemetry is not current.

6. What does "REAL" account mode mean?

The REAL badge indicates that the broker-reported MT5 trade_mode is set to live real-money execution. The system reads this metadata directly from MT5 API properties and never assumes real mode based on account balance or server naming.

7. Is automated trading execution currently enabled?

No. Automated trading execution is strictly HARD DISARMED across the entire system. In accounts.json, all 20 configured accounts maintain trading_enabled: false. The website is physically and logically incapable of placing or altering orders.

8. How do I access the dashboard?

Access requires sign-in via the Sign In page using an authorized operator email or Cloud SSO link. Authenticated users receive a read-only fleet overview of all 20 accounts. Public anonymous visits without a valid JWT are rejected with HTTP 401.

9. Why is an account shown as DISCONNECTED or AWAITING CREDENTIALS?

An account appears disconnected if its local MT5 terminal process is closed, if broker authentication fails (such as AUTH_FAILED_ERROR_6), or if login credentials have not yet been provisioned in the local environment. Unconnected slots (e.g. accounts 004 through 020) are honestly labeled AWAITING_CREDENTIALS rather than showing simulated values.

10. How are account permissions assigned?

Permissions are governed by role-based access control (RBAC) in our Supabase database. Standard authenticated users receive global read-only visibility across the 20 accounts. Elevated administrative roles (such as ADMIN or SUPER_ADMIN) require verified database profiles linked to confirmed email identities.

11. How do I contact customer support?

For operational assistance, dashboard access questions, or platform telemetry inquiries, you can contact our official customer support team directly at supportvortexbot@gmail.com. When emailing, please include your registered operator email to expedite verification.
